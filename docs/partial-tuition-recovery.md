# Partial tuition recovery and monthly cleanup

No new scheduler, Cloud Run service or listener. The existing cleanupExpiredPendingStudents runs at 03:00 Africa/Accra on the first of every month (0 3 1 * *). Unpaid trial cleanup also moves to this cadence. Trial and course access deadlines remain independent of physical cleanup. The existing batch cap remains 50 candidates per invocation; overflow waits until the next run.

A reconciled partial course with explicit dates is eligible for recovery after its recorded access/payment deadline; the final recovery day is 30 calendar days after the later of the recorded dates. Payment on the final day is permitted; the next day is the new-registration cutoff. For example 5 Dec 2026 -> 4 Jan 2027 -> 5 Jan eligibility -> 1 Feb monthly cleanup. No credit is transferred. Existing signed agreements must authorize forfeiture; verify before enabling against historical accounts. Inconsistent data, unresolved payment events, ambiguous identities, upgrades with separate lifecycle and other entitlements are protected. The existing legacy trial deletion protections remain.

Deploy the existing Firebase worker and API, and update the existing level-enrollment-sheet Apps Script web app from apps-script/level-enrollment-sheet.gs (no new trigger). Set COMPLETED_SPREADSHEET_ID to the existing completed-list spreadsheet, ensure the web app's account can write to it, and redeploy the existing web app. It must acknowledge the Terminated Enrollments archive before purge proceeds. Historical payment records remain intact. The existing Announcement deletion webhook must also confirm cleanup. Test with nonproduction data before deployment.

The completed archive includes the authoritative notice recipient (company for organisation-funded tuition). The separate Contract Reminder Apps Script is not changed by this release; partner-aware overdue reminders and final-notice delivery need to be integrated into that existing project. No new scheduled notification job is introduced.
