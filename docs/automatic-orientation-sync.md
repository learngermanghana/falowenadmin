# Automatic orientation sync for eligible students

The Orientation sheet is updated from **canonical student Firestore changes**, not only single-student payment-document updates. Group Paystack payments create allocation documents and mark the parent payment paid, but those parent records have no single studentId. The previous payment-document listener therefore missed organisation students.

A new `autoSyncApprovedStudentOrientation` function listens to `students/{studentId}` updates, including (1) verified first or subsequent tuition recorded on the student, (2) staff-confirmed class assignment or change, and (3) status changes for an already-paid student. It does not treat Admin `initialPaymentAmount` (a proposed payment) as received funds. An active unpaid trial continues to be handled by the separate operational trial sync; a pending/unpaid organisation approval does not receive paid Orientation treatment.

An organisation's requested class is assigned on owner approval **only when** its ID, class name, CEFR level and start date match the existing Firestore class exactly. Unmatched or stale requests remain unassigned, and `organisationClassAssignmentPending` stays true for the owner's review. The Orientation handler returns `confirmed_class_missing` with the student's `orientationAutoSync.status = waiting_for_class` rather than repeatedly failing or sending to a guessed class.

The original `autoSyncPaidStudentOrientation` payment-document listener remains deployed for individual tuition, but skips organisation group parent records (which have no studentId). This avoids changing an existing Eventarc production trigger in place or duplicating an individual student's initial receipt. The new student-update listener handles organisation-funded student writes and later approved-class/status changes for previously paid individual students.

The sync uses the selected live class's level/start date, and writes a status marker `orientationAutoSync` on the student record. After success the existing `syncKey` prevents another send for the same student/class/date. The existing Orientations Apps Script can upsert by student code/email. Manual `/orientation` remains an available repair path for existing records without a fresh update; no new poller, separate paid service or duplicate account is needed.

Deployment: `scripts/patchAutomaticOrientationSync.mjs` regenerates `functions/index.js` for the Firebase deploy. In Firebase, confirm the **new** `autoSyncApprovedStudentOrientation` trigger has **students/{studentId}** and the original `autoSyncPaidStudentOrientation` remains on **payments/{reference}**. Both reuse the existing `ORIENTATION_APPS_SCRIPT_URL` and `ORIENTATION_SYNC_SECRET` are configured. After a test group payment or staff-approved class assignment, check `orientationAutoSync.status` and one Orientation sheet row. If the approved learner is not yet paid and has no active trial, the correct behavior is to wait for eligibility rather than send a false paid Orientation message.
